# KB rerank buys +0.04 Hit@5 but no candidate count fits the 2s seam budget

## Context
The KB seam sends vec+lex to the ko-qmd daemon with `rerank:false`. The KB eval README rejected rerank on
2026-09-18 at 13~15s per query against a 2s seam budget. After the PR #11 re-embed, `qmd-full` measured
Hit@5 0.97 / Recall@5 0.76 against 0.93 / 0.69 for the seam path. This session asked whether a smaller rerank
candidate count (`candidateLimit`) keeps the gain inside the budget.

## Findings
- The whole gain is rerank. REST `/query` runs the caller's `searches` as given and never expands, so
  `qmd-full` = the seam payload + `rerank:true`.
- Rerank fixes all three standing MISSes (q03, q37, q38) at candidateLimit 30–40, and loses q16.
- One candidateLimit-40 dump replays every smaller N exactly offline: candidates are the top N by RRF rank,
  a rerank score depends only on (query, chunk), and `blendRerankScore` takes N. Live runs at N=10/15/20
  matched the offline numbers.

| N | Hit@5 | Recall@5 | MISS | cold median | cold p90 |
|---|---|---|---|---|---|
| no rerank | 0.93 | 0.69 | q03,q37,q38 | 399ms | 744ms |
| 10 | 0.93 | 0.73 | q03,q16,q38 | 2314ms | 3091ms |
| 15 | 0.95 | 0.76 | q16,q38 | 3719ms | 4345ms |
| 20 | 0.95 | 0.75 | q16,q38 | 4592ms | 5176ms |
| 30 | 0.97 | 0.76 | q16 | not measured | not measured |
| 40 | 0.97 | 0.76 | q16 | 5614ms | 8104ms |

- Rerank costs about 190–220ms per candidate chunk (N=10–20). Fitting N=15 into a 2s p90 needs about 80ms
  per chunk, 2.5–3× faster.
- Latency must be measured cold. The rerank cache is keyed by (query, model, chunk), and after one `qmd-full`
  run every golden query replays in about 0.4s. Each config ran on its own `sqlite3 .backup` copy with
  `llm_cache` emptied, with the daemon up, on Metal. The first query (model load, 9.3s) was dropped.

## Decisions
- The seam stays on `rerank:false`. The 2026-09-18 rejection holds with today's numbers: N=40 at 5.6s median,
  8.1s p90.

## Rejected
- Hub-doc demotion (`retro-*`, `plan-*`): already rejected in the KB README at 0.93 / 0.68.
- Measuring latency on the real index: the warm cache makes it read ~0.

## Open
- A faster reranker or smaller rerank chunks: the number to beat is about 80ms per chunk at N=15.
- q16 drops under rerank at every N ≥ 10. Not analysed.
- The KB README's `qmd-full` row (0.95 / 0.78, 13~15s) and "not measured whether qmd-full fixes the three
  MISSes" are stale. Updating them is a KB repo change, not done here.
